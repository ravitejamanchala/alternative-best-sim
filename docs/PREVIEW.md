# Isolated preview deployment plan

No deployment has been executed. Source can be reviewed and tested locally before any remote operation.

1. Apply the desired network configuration in cloud environment settings (`api.github.com`, `manchala.co.uk`, `nominatim.openstreetmap.org`, `overpass-api.de`) and publish the updated environment when the product requests publication. The draft currently requests unrestricted access; the running policy remains restricted. Enabling the required domains enables access; it does not deploy this application. The current instance still enforces the prior policy.
2. Retry repository discovery through native Git and the GitHub API. If `ravitejamanchala/slaydrive-world` exists, fetch/inspect its refs before integrating anything. Otherwise create a **private** separate repository. Push only `development/world`. The user explicitly authorized repository creation and development-branch pushes. Never force-push or push into an existing learner/admin repo.
3. Use a new Cloudflare Pages project such as `slaydrive-world-preview`, with build command `npm ci && npm run build` and output `dist`. Create a development branch preview. Do not reuse `learner-drive-app`, the admin project, custom domains or DNS records. Require deployment credentials for this new project; keep them out of Vite variables and logs.
4. For online features deploy the separate Worker named `slaydrive-world-api`, with an isolated Neon database, migrated schema, restricted application role, explicit Clerk administrators and exact frontend origin. Supply Worker secrets securely. Use separate development Clerk keys/instances and no production learner database.
5. Run the UI suite with `STUDIO_URL` set to the resulting preview. Verify real admin and non-admin sessions, optimistic-concurrency conflicts, live provider quotas, and immutable publication records. Test on the reference hardware targets in `STATUS.md` before claiming desktop/mobile performance.
6. Integrate `dist-adapter/slaydrive-world-adapter.js` only in a separately reviewed learner **development** build if full World scene loading is desired. Pass the existing Three.js scene to `loadWorldTrack(scene, json)`. Use its `network` with the existing assessment code and its `rendering` for the shared scene; keep normal assessment initialization intact. `.export()` preserves the complete envelope. Do not ship a native-network-only import as a complete scenery import. The local read-only overlay and actual learner UI tests are provided in `LEARNER-INTEGRATION.md`; retain a separate learner development branch and repeat the course/profile checks before any production decision.

The local source commit and Git bundle are reviewable without GitHub access. Fresh-task restoration and remote push are separate claims and have not been validated by saving an environment draft.
