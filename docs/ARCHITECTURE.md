# World pipeline and contracts

`world/osm.ts` preserves stable `osm/type/id` identifiers, tags, footprints and shared node IDs. Building relations stitch outer/inner rings; shops attach only to containing solid footprint area, never courtyard holes. Missing source members are reported. One-way `-1` is preserved; roundabouts are directed unless explicitly tagged otherwise. Known unsupported conditional/via-way restrictions block route construction. Source access restrictions exclude non-drivable/private ways.

`World` stores source objects, authored additions, object overrides and global node overrides separately. Regeneration reconciles source IDs. A disappearing edited source is retained explicitly as an authored addition with a diagnostic. New geographies save the previous unsaved world as a revision before replacement. Regeneration is currently matched by the exact geographic origin; moving a region creates another world rather than incorrectly applying metre offsets from a different origin.

`compiler.ts` offsets whole source polylines with Clipper (1 mm grid, 2.5 cm arc tolerance), preserving PolyTree hole nesting. Polygon unions produce the shared asphalt boundary. Pavement is the union of eligible offset envelopes **minus** the shared asphalt and authored gap polygons. This eliminates internal pavement walls and overlapping approach strips. Explicit no/separate sidewalks are not synthesized; one-sided tags produce one-sided envelopes. Unknown sidewalks are clearly estimated. A 1.8 m default is an editable design assumption, not proof of surveyed footway width or DfT compliance. Mapped centreline density determines curve accuracy; no curve-smoothing invention is applied.

Geometry checks flag self-intersections, duplicate segments, missing sources and building/roadside clearance conflicts. Footprints are preserved even when they disagree with estimated road widths. Errors block the simulator adapter export, while lossless world saves preserve invalid drafts for repair. Exact building footprints and holes feed both extrusion and collision polygons. Clearance uses the same asphalt surfaces; rendering and physics use the same world coordinates.

The compiler runs in a dedicated Worker. A stale active job is terminated, its promise rejects with AbortError, and only the current job can update the editor. Idle workers retain a bounded 512-entry small-road offset cache. The global road union is rebuilt for topology correctness; rendering is not yet fully incremental. No tile-specific road buffers are generated: adjacent road fragments are unioned before render chunking, so tile edges cannot introduce separate pavement end caps.

Buildings are batched by 100 m cell with per-vertex material colours; original hidden meshes retain exact picking. Windows are instanced by cell. The viewport culls distant building cells and hides window detail beyond 240 m during driving. Shadows default off. SwiftShader/llvmpipe use 0.75 pixel ratio; hardware devices use up to 1.5. A spatial grid limits candidate physical-collision polygons. Unloaded/recompiled geometry and materials are disposed. Metrics show frame timing, calls, triangles, geometries and pixel ratio. Detailed hardware GPU profiling and streaming of much larger regions remain outstanding.

`sim/physics.ts` loads the byte-identical upstream `createPlayer` and delegates its update at 1/120 s substeps. Input samples support keyboard, touch and standard gamepads. A geometric collision adapter tests the oriented 4.3 × 1.8 m vehicle rectangle against exact building polygons; small roadside objects use conservative radii. Collision restores the previous pose and stops velocity. This is a stopping response, not a rigid-body damage or suspension model. Rendering uses the original procedural car; proprietary model files were not copied.

`sim/learner-bridge.ts` is an opt-in loader exposing the upstream native network, shared WorldScene, spawn and plan and a complete re-export function. It does not instantiate an examiner or disable an existing examiner. The read-only learner development overlay uses the original `createTest` and UI with this scene; see `LEARNER-INTEGRATION.md`. Free drive in World has no dependency on assessment, lessons, pass/fail or learner-cloud state. Normal learner assessment modules were left untouched and their existing tests were run.

Authored junction polygons enter the same asphalt/envelope unions as source centreline roads. Lane boundaries and road-divider paint compile to polygon geometry, keep dash phase across source vertices, and clip to asphalt; automatic dividers are removed from known topology junction conflict areas. Explicit incoming-approach lines use connected-road widths for an estimated setback and reject outbound one-way approaches. Pavement-gap zones subtract from the shared pavement union. These source/manual objects and all control points remain lossless in World envelopes.

Flat roads/colliders/buildings share Y=0. Nonzero-layer roads are excluded and labelled. No vertical-datum accuracy is claimed. The projection uses a WGS84-radius local equirectangular map about an explicit latitude/longitude origin; its inverse is exact for the convention, but it is not British National Grid surveying. Native network conversion uses decimetre arrays and preserves the metre-accurate original world in the extension.

## UK guidance and uncertainty

Review dimensions/markings against DfT _Manual for Streets_ and the _Traffic Signs Manual_ before publishing a route. These references inform terminology and the explicit distinction between designed defaults and mapped facts; no regulatory compliance certification is made. OSM speed values without a unit are converted from km/h; explicit mph tags stay mph. In the absence of a tag, the inspector identifies the placeholder speed as uncertain. Lane-centre paint is displayed only when explicitly tagged, and manual markings are authored overrides. Signals, crossings and stop/give-way approaches are not inferred from road classification.

References: https://www.gov.uk/government/publications/manual-for-streets and https://www.gov.uk/government/publications/traffic-signs-manual . These links document review sources; live retrieval was not verified in the restricted environment.
