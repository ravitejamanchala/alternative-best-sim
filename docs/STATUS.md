The draw-call reduction is about 59%; the desktop software-rendered frame rate is still below target. Mobile viewport interaction succeeded, but it is not a physical-phone performance result.

## Remaining product limitations

1. **Geographic completeness.** The Cambridge fixture lacks relations, so its courtyard and turn-restriction coverage is incomplete. Tests exercise real relation parsing using explicit fixtures. Missing source nodes are diagnosed. Known unsupported via-way/conditional restrictions refuse routing. The loop search is bounded and reports when it cannot find a suitable connected cycle.
2. **Junction/lane authoring.** Road control points share topology. Authored junction polygons, independent lane guides, lane count/divider paint, explicit endpoint connections, pavement-gap zones, and incoming stop/give-way approach placement are implemented. Junction polygons enlarge the shared asphalt union; shrinking below source road widths requires editing those widths. Automated surveyed pavement-boundary ingestion and complete source-facing interpretation remain incomplete. Approach setbacks and unknown pavement widths are explicitly estimated. Static signals are manually oriented and have no invented phases.
3. **Street/building detail.** Footprints, holes, source tags, heights, storeys, use and roof tags persist. Original terrace/semi-detached door rhythms, commercial/residential/industrial windows, shop/pub frontages and simple tagged roofs are rendered. Complex roofs and architectural styles remain simplified. Contained shop names receive an estimated outer-wall frontage; this is not surveyed facade placement. No estimated height is presented as surveyed.
4. **Traffic.** Toggles control moving ambient vehicles/pedestrians and conservative player contacts. Ambient actors are not a complete UK traffic AI: there are no authored signal phases, pedestrian crossing decisions, comprehensive turn-restriction planning for traffic, multi-car rigid-body response or assessment behaviour. Static placed signals are explicitly identified as inert. Kerb traversal, suspension and road elevation are simplified/flat.
5. **Optional sources.** Licensed bounded Overture Polygon/MultiPolygon GeoJSON gap-fill import works, preserving stable feature/part IDs, full properties and courtyard holes. Repeat import retains existing manual edits and deletions. Features overlapping existing footprints are excluded, as described in the import dialog. Mapillary has an optional authenticated server API for reference positions; an embedded official viewer is not implemented. There is no automatic imagery-to-geometry claim. Elevation-aware driving remains disabled until road, building and collision elevations share a documented datum.
6. **Learner integration.** The native loader and opt-in shared-renderer bridge are tested, including unchanged assessment state. The existing learner's production UI does not load custom World scenes automatically. A read-only local development overlay now imports/exports through the actual learner UI and shared renderer, with original assessment fault handling and lossless browser reload checks. A normal source integration on a learner development branch, full course/profile regression, authored-control assessment semantics and exact World collisions in the learner remain required before a learner release; see `LEARNER-INTEGRATION.md`. No learner deployment was modified.
7. **Hosted workflow.** Live place/address/test-centre search, live Overpass results, real administrator/non-administrator Clerk sessions, a real Neon instance and publication records need configured services. Automated API tests use an injected token verifier and an actual local Postgres engine; they do not establish live credentials. There is no deployment or remote GitHub push yet.
